# Prosify

**Correcting formatting bias in large language models.**

Prosify is a research project tackling the systematic over-formatting habit that contemporary LLMs develop through RLHF — defaulting to bullet points, bold headers, and templated structures even when flowing prose would serve the reader better. This repository is the home of the project's code, the FormatBench dataset, and (eventually) a trained model that fixes the problem.

## Status

**Phase 1 complete:** FormatBench v1.1 dataset published on Kaggle
**Phase 2 in progress:** Train/val/test splits, baseline experiments
**Phase 3 planned:** DPO fine-tuning + evaluation
**Phase 4 planned:** Trained model release on HuggingFace, paper-style writeup

## The problem

Large language models trained with RLHF systematically over-format their outputs. This is the everyday friction people experience when they ask an LLM to draft an email, polish a paragraph, or explain a concept casually and get back a slide-deck-style response. It's a close cousin of the documented length bias in RLHF (Singhal et al., 2023), where reward models inadvertently reward surface features that correlate with but don't constitute the response quality.

Prosify treats formatting register as an explicit, learnable optimization target, with the goal of producing models that match formatting to context rather than blanket-applying structure.

## The FormatBench dataset

The dataset comes in two parts:

| File | Examples | Purpose |
|---|---|---|
| `formatting_pairs_v1.jsonl` | 551 | Training data — `chosen` is prose, `rejected` is over-formatted |
| `adversarial_holdout_v1.jsonl` | 40 | Evaluation-only — `chosen` is clean structure, `rejected` is meandering prose |

The contrast between the two files is intentional. The main dataset teaches the model to drop over-formatting in contexts where prose serves better. The adversarial set verifies the model retains appropriate structure where structure genuinely helps (recipes, install steps, comparisons, troubleshooting, reference lookups) rather than reward-hacking into blanket bullet-removal.

### Row schema

Each row contains:

```json
{
  "prompt": "Write me an email to my manager...",
  "chosen": "Hi [Manager], I'd like to request...",
  "rejected": "Subject: Leave Request\n\n**Reason:**\n- ...",
  "context": "email_draft",
  "register": "us_tech_casual"
}
```

## How the dataset was built

The dataset was constructed in 10 batches, each generated by a Python script that appends ~50 examples to the running JSONL file. All 10
generation scripts are in `scripts/` for full reproducibility and audit.

For each example:

- The `rejected` response (main dataset) was deliberately crafted to mimic the actual failure modes of contemporary frontier LLMs:
  emoji-prefixed bullets, bold mid-paragraph labels, "## Section headers" inserted into running prose, "Pro Tips:" / "Key Takeaways:"
  callout boxes, "Here's a polished version:" meta-commentary.
- The `chosen` response was written as a contextually appropriate alternative, with deliberate variation in voice across examples.
- The adversarial set inverts this pattern i.e `chosen` uses clean structure where structure genuinely helps; `rejected` is meandering
  prose that buries the actionable content.

Generation was assisted by large language models with human curation and review. All examples were reviewed in batches before inclusion.

## Recommended evaluation protocol

For meaningful evaluation of a model fine-tuned on this dataset, use both metrics:

1. **Win rate on a held-out test split of the main dataset** — does the trained model produce more appropriate prose where the main dataset taught it to?
2. **Adversarial preservation rate on the held-out set** — does the trained model still produce structured responses where structure
genuinely helps?

A model that scores high on (1) but low on (2) has reward-hacked into blanket structure-removal and is weaker than the base model in practice.

## Limitations

- **Single-author voice**: All main-dataset `chosen` responses authored by one annotator. A trained model will inherit this voice.
- **English only**: no multilingual coverage.
- **No demographic diversity** beyond the email register tags (Indian-corporate, US-tech-casual, global-neutral).
- **Modest size**: 591 total examples is enough for a measurable DPO effect but not dramatic.
